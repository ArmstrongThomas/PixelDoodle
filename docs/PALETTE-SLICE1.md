# Editable palette and square picker

Picker field is square: 104x104 on DS and 152x152 on 3DS. Hue, current color/RGB/hex and a labeled vertical Palette strip sit to its right. One button toggles Picker/Palette. Both palettes scroll vertically by dragging on swatches, with a thin scroll indicator and no paging buttons. The Palette page uses five columns of square swatches and has no opacity control; alpha is adjusted in Picker.

Palettes contain 1–256 ordered RGBA colors. Tap and release a swatch to use it. Edit opens the selected entry in Picker with Save and Back replacing the toggle. Save updates that entry and returns to Palette; Back discards the edit. Leaving through the toolbar or a hardware action also discards the edit. Regular picker changes still apply immediately. Add appends the current color; Remove retains at least one entry. Existing artwork is never recolored.

Move vertically more than five pixels within 150 ms to scroll without selecting or reordering. Hold still for 150 ms then drag to reorder; the target shows MOVE, and hovering at the list edges scrolls to further entries. Release commits the move. Reordering is disabled while editing a color, but the vertical strip can still scroll or supply a replacement color.

This is a global device palette, separate from project documents. Mutations save on stylus release to alternate app-owned palette0.bin/palette1.bin slots. PPL1 records are 1040 bytes: magic, little-endian sequence and count, 256 RGBA words, then CRC32 of the preceding 1036 bytes. Counts and CRC are validated; the newest valid slot wins. Writes flush/sync/close and read back. Failure leaves changes usable in RAM and displays that they were not saved; another edit retries. No FAT power-loss guarantee. Missing palettes use the original eight defaults. Project palettes and palette-file import/export remain later work.

Host checks cover add/edit/save/back/remove, count limits, persistence and corrupt-newest fallback, 150 ms hold threshold, drag scrolling, edge-scroll reorder, immediate color use and optimized/full-render equivalence on both native layouts. Existing layer/file/drawing regressions and all three build/package checks pass. Native layouts inspected. Emulator interaction and hardware acceptance are pending for this candidate. melonDS without configured storage cannot persist palette edits.

Performance follow-up: scrolling and reorder updates skip document compositing and top-screen redraw. Only visible swatch rows are visited; full HSV fields use a 256-entry temporary hue ramp with the same rounding, and alpha strips calculate two checker shades per column. No persistent framebuffer allocation was added. Scroll/full render equivalence passes on DS and 3DS; user timing/feel acceptance remains pending.
