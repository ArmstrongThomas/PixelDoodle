# Documents, history and process recording

Proposed decisions, 2026-10-14. Current prototype uses the simpler PDD1 format in [prototype status](PROTOTYPE-0.1.0.md); the format below is future work. This is a design contract to refine with M0 fixtures, not an implemented binary specification.

## Reuse the existing Doodle recording foundation

The user correctly points out that Collab Doodle already records drawing strokes. Local source inspection confirms `socketHandlers.js` logs `draw.batch` details with points, RGB, size, shape, feather and bounds, wrapped in canvas audit metadata. `moderationStore.js` provides drawing-review/timeline queries, timestamps, dimensions and epochs. The NDS command path already resolves compact stamps with size, shape, feather and stroke-start flags. This is substantial reusable design, not a greenfield recording problem.

Adapt its ordered drawing-command model and compact NDS stamp representation. Add layer ID, RGBA, explicit stroke boundaries, relative timing and a renderer-semantics version. Implement a bounded local append writer in portable C instead of bringing Node/SQLite onto DS. Preserve actual rendering order. Existing network batching cadence is not necessarily individual input timing; new local events should capture sample deltas explicitly.

The current timeline projection does not expose feather in its returned event shape even though the draw log stores it; it also marks paste patches non-replayable and treats clear/rollback as reset categories. Therefore a timeline API response alone is not yet a lossless portable project recording. Native and NDS paths can differ in interpolation policy. This is a reason to formalize resolved stamps and complete mutations, not a reason to discard the existing approach. No server code or historical audit/user data has been copied. Build synthetic adapters/tests against these concepts; reuse private implementation only in a future appropriately private component after provenance review.

## Authoritative project state

Provisional `.pxp` container: little-endian fixed header with magic, major/minor version, required-feature flags, dimensions, document ID, revision sequence and renderer semantics ID. Chunk records contain type, flags, stored length, decoded length and CRC32. Core chunks: document metadata, palette, layer directory, tile directory/data, flattened thumbnail and optional replay descriptor. Missing tiles mean transparent black. Layers have stable uint32 IDs independent of order, UTF-8 names, visibility, lock, 0-255 opacity and explicit blend enums. Device keyboard can remain ASCII initially while preserving unsupported name bytes and rendering a fallback glyph.

Canonical pixels are straight-alpha RGBA8888, sRGB-encoded channels, transparent RGB normalized to zero. Tile coordinate and layer ID form stable keys. Use 16x16 tiles, raw or independent zlib-compressed chunks, stream one chunk at a time. Raw storage remains a valid low-CPU option on DS. No ZIP extraction paths or embedded executable content. A flat validated index supports seeking without inflating the entire document.

Do not use `.aseprite` as the native save format: its animation-oriented structure adds unnecessary scope. First interchange is PNG RGBA, with indexed PNG expanded losslessly to RGBA on import. Preserve transparency; reject unsupported dimensions before decode. No implicit resize, quantization or flattening. Import can create a new project or layer after capacity checks. Export merged visible PNG, optional individual layers plus a simple manifest later; JPEG is not a pixel-art default. `.aseprite`/OpenRaster import may be later work with an explicit supported subset.

Read limits must cover integer overflow, dimensions, layer/tile count, duplicate keys, overlapping offsets, total decoded bytes, compression ratio/work, invalid UTF-8 length and unsupported critical chunks. Unknown optional chunks can be skipped; unknown required features refuse editing rather than silently discard data. Corrupt thumbnails never validate corrupt project data. CRC detects damage, not authenticity.

Saving uses generation files and a validated manifest: write a new generation, flush/close, read back and validate, then update an alternating small manifest slot with sequence+checksum. Keep the previous valid generation until the next verified save. On startup select the newest complete referenced generation; offer recovery of a complete orphan. Do not assume FAT rename or flush proves power-loss atomicity. Fault-inject every write boundary and test real media with synthetic projects. Free-space preflight includes the old and new generations, replay and scratch. Uncertain saves retain the old generation and a visible unsaved state.

New app-owned paths are proposed under `fat:/PixelDoodle/` or a user-selected supported SD root and `sdmc:/3ds/PixelDoodle/`; separate projects, settings and private pairing credentials. Never use CollabDoodle paths. No files have been written on a console.

## Compositing contract

Implement integer source-over with source pixel alpha multiplied by layer opacity. Freeze round-to-nearest rules and exact order in versioned golden fixtures; use wide intermediates. Blend functions operate on unpremultiplied channels, with alpha-aware source-over around them. Multiply, Screen and Overlay follow the independently documented [W3C compositing definitions](https://www.w3.org/TR/compositing-1/); Overlay branches on backdrop, not source. Transparent backdrops must not become black under Multiply. Do not simply blend two RGB values while ignoring their alphas. Normal, opacity zero/full, transparent pixels and reordered layers must have explicit tests. UI checkerboard never enters exported pixels.

Use Aseprite's MIT-scoped document compositor as a reference for alpha edge cases after license checks; do not copy whole application code. Define our own exact sRGB integer behavior instead of promising bit-for-bit compatibility with every Aseprite version. Browser Canvas blend operations are display conveniences, not the deterministic reference; use the same core compiled to WASM.

## Undo and redo

One pen contact is one logical transaction; fill, selection move, merge and each layer-property edit are transactions too. Capture each touched tile's before state once and its final after state, plus metadata changes. Store bounded tile deltas or whole tiles according to size. Active stroke data is tentative until commit; cancel restores before images. A redo after undo reapplies exact after images, not a potentially changed brush algorithm.

Undo pool is byte-bounded and separate from the recording stream. Evict oldest complete history entries only. A new edit after undo clears the redo branch in the editor, while the recording retains what the user actually did. Deleted layers retain restorable pixels in history; merge must preserve all source layers until commit. Slider drags coalesce into one property edit.

Preflight worst-case allocation for fills/merges/imports. Keep a reserved active-transaction pool (initially one before+after active layer, plus metadata) independent of history eviction. Long strokes may change the whole layer; store the touched-tile bitmap, not unlimited duplicate before images. If an operation exceeds the configured reserve, reject before mutation or explicitly stage it through a validated disk transaction with progress. Never silently make an edit non-undoable. Rejecting a large multi-layer operation is acceptable in early profiles. Small-stroke and full-layer memory tests set supported caps.

## Recording and playback

`.pxr` is an append-only companion recording, linked by document ID, base snapshot hash and sequence range. A shareable bundle contains a standalone base snapshot plus replay chunks and any referenced import/patch assets. It can be uploaded separately from the current project. Project saving does not require replay from the beginning; current layers remain authoritative.

Events: BeginStroke, StampBatch, EndStroke, LayerAdd/Delete/Reorder/Rename/Visibility/Lock/Opacity/Blend, Patch/Import, Fill, Merge, Undo, Redo and recording pause/resume boundaries. Store relative monotonic time, action sequence, transaction ID and layer ID. Rendering records resolved integer positions/size/coverage/colors after pressure filtering and pixel-perfect processing; UI ADC samples and machine-specific clocks are unnecessary. Symmetry/tiling metadata explains settings but resolved stamps avoid future geometry drift. Any random tool gets a fixed algorithm ID and seed or resolved results.

Recorded Undo/Redo includes a self-contained patch/metadata transition or a reference to an immutable patch blob within the recording. It must not rely on the player's undo ring or a transaction predating a seek checkpoint. This deliberately costs more bytes for large undo operations while allowing bounded-memory seeking. Import and merge similarly record required content; no references to unavailable local paths. Entire transactions use begin/chunks/commit markers and checksums. Recover only through the last valid committed transaction after a truncated tail.

For within-stroke animation keep compact timestamped stamp batches. Pixel-perfect tentative tails are not irrevocably recorded before resolution; either delay the tail by one sample or record its explicit correction patch. EndStroke carries a state checksum for diagnostics. Strokes interrupted by storage failure remain drawable in RAM if possible, but mark recording incomplete, stop claiming complete replay and prompt to save/restart recording from a new base. Never quietly discard events while showing recording as healthy.

Process playback shows actual order, including undone mistakes and layer changes. A future clean-final-history export is a separately derived artifact: simply deleting undone commands can break dependent fills, merges and imports. Default public publication is still-only; author must explicitly include playback and review it because old/hidden/deleted content may be revealed. Recording can be paused; resume begins from a new checkpoint and visibly marks the gap.

Use 16-64 KiB output buffers, flush at pen-up/idle, and cap buffered work. At 60 samples/sec and roughly 8-16 bytes per resolved sample, continuous raw stroke records are about 1.7-3.5 MB/hour before transaction overhead, mirroring and patch/checkpoint payloads. This is an estimate, not a storage guarantee; dense imports and undo patches can dominate. Set a configurable session byte limit, show remaining space and rotate recording segments rather than monopolize RAM. Test worst-case data, not just compressible lines.

Checkpoints: self-contained layers + metadata + replay offset/time/semantics ID. Start with checkpoints at session start/save and after roughly 200 actions or 60 seconds of active drawing, whichever is later; tune by device. Write at pen-up with progress if necessary, avoid periodic full snapshot work while drawing. Bound checkpoint bytes (e.g. 25% overhead target, measured) and use longer intervals on DS. Website worker may generate additional indexed checkpoints after validation. Seek loads nearest previous checkpoint and replays forward; old checkpoints must not require discarded undo memory. Compare hashes at checkpoint boundaries. Browser seeking target <1 second for typical projects, measured before claim; DS may show progress.

Version both container and raster semantics. Preserve old replay interpreters or explicit lossless migrations; unsupported versions offer the saved still image and an explanatory message. Never reinterpret old brush IDs silently. Native/host/WASM replay of synthetic recordings must match document hashes at every transaction before feature acceptance.

Playback is a sequence of drawing instructions rendered over time, not an encoded video. Optional MP4/WebM export belongs in a capped desktop/server worker that renders frames through the same core and passes them to an audited encoder. Review the chosen encoder build's licensing separately. Offer speed/idle-gap compression, nearest-neighbor integer scaling and a still hold at the end. DS/DSi should not encode video in real time.
