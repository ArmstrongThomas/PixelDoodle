Pixel Doodle animation plan

Can a DS Lite hold a real animation, how much an optimization pass frees first, how frames would be stored, and mockups of the timeline, onion skin and frame shortcuts.

Yes: 30+ frames fit in RAM on a DS Lite for typical sprite sizes, with no card streaming. After the optimization pass, DS mode has about 1.6 MiB for frames. A 64×64 sprite with 4 layers costs about 7 KiB per frame, so roughly 200 frames. A busy 128×128 piece with 4 layers holds 50 to 100. DSi and 3DS hold far more.

Card streaming is only needed for large, dense canvases (8 full layers at 128×128 on DS, or 512×512 on DSi). It should wait until a card read-speed test on your DSpico says it is needed.

Where the savings come from

  • Drop the network stack from standard builds. The hidden Community feature still links its certificate bundle and pairing code (216 KiB), Mbed TLS (95 KiB), Wi-Fi (76 KiB) and the community client (25 KiB).
  • Size masks to the canvas. Four selection and redraw masks are sized for 512×512 (32 KiB each) even in DS mode, where 128×128 needs 2 KiB.
  • 16-bit screen buffers. The DS displays 15-bit color, but both screens render to 32-bit buffers first. Rendering at 16 bits halves them and shortens every screen copy.
  • Allocate on use. The clipboard, file preview and gallery thumbnails stay resident even when never opened.
  • Add measurements to Diagnostics: free heap, largest free block, card read speed and frame switch time, so DSi and DS Lite limits come from the hardware rather than estimates.

How frames would be stored

  • The current frame stays exactly as today: full-color working layers, so drawing speed and every tool are unchanged.
  • Other frames are packed into a shared pool of 8×8 tiles, the same tile size undo already uses. Empty tiles cost nothing.
  • A tile with 256 or fewer document colors stores one byte per pixel (64 bytes) instead of 256. Tiles identical to one in another frame are stored once, which is most of an animation.
  • Switching frames packs the edited tiles of the old frame and unpacks the new one. Undo records which frame each edit belongs to.
  • Onion skin and playback use cached flattened images, so neither recomposites eight layers per frame.
  • Frames hold up to 256 per project. The timeline shows a memory meter like the layer memory line, and refuses a new frame with a clear message instead of failing later.

Pan, Sample and Zoom follow your button remapping. Default Pan is A / Left and Sample is X / Up. Pan and Sample with a shoulder are unused today, so nothing existing moves. Touching the canvas or pressing B stops playback.

Build order

  1. Optimization and measurement build. The savings above, plus the Diagnostics readouts. You run it once on the DSi and DS Lite.
  2. Frames in the core. Tile pool, frame switching, undo across frames, a native file version that saves the pool directly, and the memory meter.
  3. Timeline, canvas frame strip, shortcuts and onion skin.
  4. Playback with per-frame durations and loop tags.
  5. Aseprite animation import and export, read and written one frame at a time, with linked cels, durations and tags; plus PNG sprite-sheet export.
  6. Card streaming, only if step 1's numbers show it is needed.
